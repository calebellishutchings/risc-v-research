Understanding RISC-V

This independent study examines how RISC-V systems are brought up, measured, and compared across platforms and varied implementations. It explores RISC-V as an instruction-set architecture, explaining it in a easy-to-digest manner and exploring the underpinnings that make it efficient, portable, and open.

What is RISC-V?

An Open Instruction Set Architecture

When code is written, it is compiled, or condensed, from human readable text to machine code, a combination of 1's and 0's that essentially tells the computer what to do. This machine code is inherently ordered in a certain way so that the internal components of the processor route data correctly and run, or execute the machine code so it not only does what it is programmed to do, but also to do so in an efficient manner. This ordering of 1's and 0's is planned out to form "instructions," each of which are a simple task that combined with other instructions to form any program.

Because the computer must understand each instruction, there must be some collection, or "set" of instructions that the processor can accept. Most "instruction set architectures," (or ISAs), are coporately controlled, complex, inefficient, and expensive. The researchers who created RISC-V wanted to attack these issues, allowing anyone to develop hardware components that can run RISC-V programs without paying a fee, with easy documentation, and relatively few instructions.
