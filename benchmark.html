Recalculation

How 88.96 iterations/s was obtained

The CH32 port reads the free-running 32-bit SysTick counter. Its port configuration uses FUNCONF_SYSTEM_CORE_CLOCK / 8 unless SysTick is explicitly configured for HCLK, so at 48 MHz the timer is 6,000,000 ticks/s.

Elapsed time74,193,287 ticks ÷ 6,000,000 ticks/s = 12.36555 s

Iteration rate1,100 ÷ 12.36555 s = 88.95684 iterations/s

Per MHz88.95684 ÷ 48 MHz = 1.85327 iterations/MHz

The report’s 12 seconds and 91 iterations/s are integer presentation values. The raw tick calculation retains the timing precision needed for the stated result.

Configuration and controls

What the port does around the timed interval

A

Before timing

It initializes CH32V003fun, captures/clears reset flags, starts UART, gives a five-second monitor-attach window, and displays an LED startup pattern. These actions are outside CoreMark timing.

B

During timing

The timer is SysTick; interrupts are disabled. The only added service is a linker wrapper around CoreMark’s list workload to refresh an option-byte-selected independent watchdog, without UART output in the normal performance image.

C

After timing

The report is emitted over UART PD5 at 115200 baud. A solid LED means setup/timing has begun; a repeating blink confirms that the report completed even if serial capture was missed.

Reproducibility checklist

Compare like with like

  • Record the same CoreMark version, data size (1,200 bytes here), memory model, seeds, iteration policy, compiler, and flags.
  • Use the raw tick count and the known SysTick rate; do not calculate from the rounded seconds field.
  • Keep serial I/O, debugger traffic, diagnostic wrappers, and interrupts outside the timed interval.
  • For validation work, use the project’s validation task and its known CRC expectations. Do not present a run with the captured validation warning as validated.
