Current experiment

PicoRVD port and CH32V003 performance measurement

This record combines the porting work and its first benchmark result. It is written for readers new to RISC-V and separates implementation facts from the limits of the measurement.

Context

What was built

PicoRVD is firmware that lets a computer use a Raspberry Pi Pico as a USB debugger and programmer for supported RISC-V targets. This work moves it from the original Pico/Linux assumptions to the Pico 2’s RISC-V platform on Windows. The resulting tool is used to program a CH32V003 target and capture serial output from its benchmark.

Benchmark method

CoreMark-derived measurement

CoreMark is a compact processor benchmark. The CH32V003 port uses a free-running SysTick counter, a UART report channel, and static on-chip memory. Startup messages and LED indications occur before or after the timed region. During normal timing, interrupts are disabled and no UART output is produced.

Calculated result

Rate derived from the raw timer count

CoreMark prints whole-number seconds and iterations per second. The calculation below uses the full tick count, so it avoids rounding the elapsed time to 12 seconds.

Interpretation

How to report this result

This is a configuration-specific CoreMark-derived measurement, not an official CoreMark score. The normal CoreMark data block is 2,000 bytes; this port uses 1,200 bytes because the CH32V003 has 2 KiB of SRAM and the benchmark must also leave room for the program stack. The captured output also states that operation cannot be validated for its performance-mode seed values.

Comparisons should retain the CoreMark version, data size, memory model, seed values, iteration policy, clock rate, compiler, and compiler flags. Diagnostic UART output and debugger traffic should remain outside the timed interval.
